2. LLM 프로그래밍 경험이 필요한 이유

생성형AI와 언어 모델의 장점과 한계를 이해

​

3. LLM의 한계를 보완하는 기술

(1) 프롬프트 엔지니어링 (prompt engineering)

프롬프트 : 언어에게 업무 매뉴얼을 제공

질문 시 존댓말X, 정확히 지시 (토큰 사용량 최소화 필요)

답변도 간단하게 하도록 지시

​

(2) 파인 튜닝 (fine-tuning)

"너는 의사가 돼야 해"

HW가 빵빵해야 한다

​

(3) RAG (Retrieval Augmented Generation)

질문이 들어 왔을 때 데이터베이스에서 관련정보 찾고 그 내용을 토대로 답변

CRM에서 활용

실험 data는 외부유출되면 안됨 - RAG 형태로 data를 넣음

미토스

​

(4) function calling & tool call

user SKT Fold7 AI DB

function calling : user의 질문에 대답하기 위해 AI와 DB가 왔다갔다 함

주어진 함수의 매개변수 형식을 명확하게 정의하고, 그 구조에 맞춰 함수를 호출하여 결과를 사용

tool call : function calling을 활용

랭체인과 같은 LLM 기반 프레임워크에서 텍스트로 요청을 보내 외부함수나 도구로 실행시킨 후, 그 결과를 처리

​

(5) 랭체인 (LangChain)

여러 개의 AI 모델이 있고, 모델을 쉽게 교체 가능

LLM을 활용하여 애플리케이션을 개발하는 프레임워크

(ex) 당 관리방법과 그 내용을 문서화 - data 수집 / 분석 / 요약 / 문서화 / 이미지 모델 => AI Service Model

Model 최신으로 변경 ; 랭그래프

​

(6) 랭그래프 (LangGraph)

여러 AI Agent를 결합해 멀티 에이전트로 구현

agent role - 규제 필요
