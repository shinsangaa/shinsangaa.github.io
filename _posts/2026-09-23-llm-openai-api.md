이 글은 9월 22~23일 강의 주제를 복습하기 위해 새로 작성한 **개념 설명 초안**입니다. 카페 강의 원문을 옮긴 것이 아닙니다.

## API를 이용한 챗봇 구조

사용자 입력 → 애플리케이션 서버 → LLM API 요청 → 모델 응답 → 결과 표시의 순서로 생각하면 이해하기 쉽습니다. 프롬프트는 모델에게 작업 목표와 필요한 맥락, 출력 형식을 전달합니다.

## 챗봇과 에이전트의 차이

일반적인 챗봇은 질문에 대한 답변을 생성하는 것이 중심입니다. 에이전트는 필요할 때 도구를 호출하거나 여러 단계를 진행하도록 설계할 수 있습니다. 다만 실제 파일 변경이나 외부 서비스 호출에는 **권한 관리, 입력 검증, 사용자 승인**이 중요합니다.

## 실습 때 기억할 점

- API 키는 코드나 공개 GitHub 저장소에 직접 쓰지 않습니다. 환경 변수 또는 비밀 관리 기능에 보관합니다.
- 요청·응답에 개인정보가 포함되는지 확인합니다.
- 잘못된 응답을 자동 실행하지 않도록 검증 단계를 둡니다.
- 사용량에 따라 요금이 발생할 수 있으므로 제한을 확인합니다.
