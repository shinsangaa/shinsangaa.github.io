1. 참고 : Convolutional Neural Network, CNN

Conv2D()는 합성곱 신경망 (CNN)에서 해김적인 역할을 하는 2차원 합성곱 층을 생성하는 Keras 함수

주로 이미지데이터에서 선, 모서리, 질감과 같은 시각적 특징을 추출하는 데 사용

​

(1) Filter(또는 커널, Kernel) 도장 찍기

Conv2D()는 이미지 전체를 작은크기의 필터로 도장을 찍듯이 지나가면서 합성곱을 수행

이 필터는 이미지의 특정 패턴을 찾고, 학습을 통해 어떤 패턴을 찾을지 스스로 가중치를 업데이트한다.

​

(2) 주요 하이퍼파라미터 (설정값) - Conv2D에서 필터개수, 커널사이즈 옵션은 반드시 있어야 한다.

filter 필터 개수

kernel_size 필터 크기

strides 보폭 : 필터가 한 번에 몇 칸씩 이동할지 결정. 기본값은 (1, 1)

padding 패딩 : 가장자리 처리 방식

'valid' (기본값) : 패딩을 하지 않아 출력 크기가 입력보다 작아진다.

'same' : 입력 이미지의 가장자리에 0을 덧대어 출력 크기를 입력 크기와 똑같이 유지

activation 활성화 함수 : 추출된 특징에 비선형성을 부여. 보통 relu를 가장 많이 사용

​

간단한 사용 예시 코드

import tensorflow as tf
# 모델 구성 시작
model = tf.keras.models.Sequential() # 모델을 순서대로 쌓는다 (이전에 모델 구성 시 인풋레이어, 히든레이어, 출력레이어와 같은 구조))
# 1. 첫 번째 Conv2D 층 (입력 이미지: 28x28 흑백 이미지)
# - 필터 32개, 필터 크기 3x3, 활성화 함수 ReLU 사용
model.add(tf.keras.layers.Conv2D(
filters=32,
kernel_size=(3, 3), # 보통 이미지특징 찾을 때 (3,3), (5,5)를 흔히 사용
activation='relu',
input_shape=(28, 28, 1) # 채널 1 = 흑백 #(이전에 모델 구성 시 Input레이어에 입력 넣는 법 (1) reshape (2) Flatten)
))
# 2. 두 번째 Conv2D 층
# - 필터 64개, 입력 크기는 앞 층에서 알아서 계산해주므로 생략
# 입력값은 첫번째 Conv2D에서 받았으므로 여기선 생략. 그러나 filter개수와 kernel_size는 지정 필수
model.add(tf.keras.layers.Conv2D(
filters=64,
kernel_size=(3, 3),
activation='relu'
))

2. MaxPool2D()

MaxPool2D() : 전체 이미지에 대한 해상도를 줄여서 처리속도를 높인다. (MaxPool 레이어는 입력값 없음)

지정한 레이어에서 가장 큰 값만 뽑고 나머지는 버림

과적합을 방지해준다. (불필요한 데이터(noise)가 들어가지 않음)

Conv2D() 코드 밑에는 MaxPool2D()가 들어감

Layer란?

Input, Con2D, MaxPool2D, Dense 레이어들은 => Model을 구성

(ex) Image 분류 - pixel의 개수(입력값), color or 흑백, 정답지 개수(출력값)을 알아야 Model 구성 가능

(3x) Image 28 \* 28, 흑백 - (28, 28, 1)

Image 28 \* 28, 컬러 - (28, 28, 3) (3장 있어야 함(R, G, B)) => reshape으로 1차원 만들거나, Flatten 필요

​

Dense레이어 : fully connected layer 완전 연결층. 가중치를 연산해 특징을 연결해줌

5. 참고 : Recurrent Neural Networks (RNN)

순차적인 데이터나 시계열 데이터(주식, 심전도 등)를 처리하는 데 특화된 신경망

​

RNN특징 - '기억을 전달'

일반적인 신경망은 고정데이터(값이 고정). 입력 데이터를 받아서 한 방향으로만 통과시켜 결과를 낸다.

RNN은 이전 단계의 처리 결과를 현재 단계의 입력과 함께 다시 자기 자신에게 입력으로 주는 Loop를 가지고 있다.

​

작동 방식 - '나는 오늘 밥을 먹었다'

step1. 첫 번째 단어 '나는' 입력 받음. 이 정보 처리하여 은닉상태 h1을 만듦

step2. 두 번째 단어 '오늘'을 입력 받음. 전에 만든 기억 h1과 현재 입력 '오늘'을 함께 고려한 은닉상태 h2를 만듦

step3. 세 번째 단어 '밥을'과 방금 전 기억 h2를 함께 처리해 h3을 만듦

​

한계 - 장기 의존성 문제

문장이 매우 길어질 경우 장기 의존성 문제 또는 기울기 소실 현상 발생

RNN 정보가 매 스텝마다 곱해지면서 전달되기 때문에 문장이 길어질수록 과거의 정보가 옅어져서 최근의 정보만 크게 반영하는 문제가 발생한다.

이 문제를 해결하기 위해 기억을 선택적으로 오래 유지할 수 있는 특수한 Gate구조를 추가한 LSTM(Long Short Term Memory) 이나 GRU (Gated Recurrent Unit) 같은 발전된 RNN 모델이 주로 사용된다.

6. 참고 : RNN의 단점을 극복한 LSTM

RNN의 장기 의존성 문제를 해결한 LSTM(Long Short-Term Memory)과 GRU(Gated Recurrent Unit)의 핵심 원리는 '게이트(Gate, 문)' 시스템

​

기존 RNN이 매번 들어오는 새로운 정보를 과거의 정보와 무조건 섞어버려서 과거 기억이 점점 희미해졌다면,

LSTM과 GRU는 "무엇을 잊고, 무엇을 기억할지"를 스스로 판단하고 조절하는 똑똑한 문(Gate)을 설치했다.

​

(1) LSTM의 원리: 컨베이어 벨트와 3개의 게이트

LSTM은 중요한 서류를 싣고 지나가는 컨베이어 벨트(Cell State)

이 벨트에는 3가지 종류의 작업자(Gate)가 붙어 있다.

​

망각 게이트 (Forget Gate)

현재 들어온 단어를 보고, 과거의 기억(Cell State) 중 어떤 것을 0으로 만들어(잊어버려) 벨트에서 떨어뜨릴지 결정한다.

​

(ex) 앞 문장에서 주어가 '남자'였는데,

새로운 문장에서 주어가 '여자'로 바뀌면 이전의 '남자'라는 성별 정보는 잊어버리도록 문을 닫는다.

​

입력 게이트 (Input Gate): "새로 들어온 이 정보는 중요하니까 벨트에 올리자."

​

현재 들어온 단어가 앞으로 얼마나 유용할지 판단하여, 새로운 정보를 컨베이어 벨트에 얼마나 추가할지 결정.

​

출력 게이트 (Output Gate): "지금 상황에선 이 정보만 밖으로 내보내자."

컨베이어 벨트(전체 기억)에 있는 정보 중에서 현재 시점에서 밖으로 출력(예: 다음 단어 예측)하는 데 필요한 정보만 필터링해서 내보낸다.

​

핵심: 이 컨베이어 벨트(Cell State)는

정보가 직통으로 쭉 흘러가는 고속도로 역할을 하기 때문에,

중요한 정보(예: 문장 첫머리의 주어)는 망각 게이트가 지우지만 않는다면

문장 끝까지 온전하게 살아남아 전달될 수 있다.

​

(2) GRU - LSTM을 축소

LSTM 원리를 그대로 가져오면서 구조를 간소화하여 계산 속도를 높임

7. 참고 : 의사 결정 트리 (Decision Tree)

트리의 기본 구조

트리는 여러 개의 Node와 이를 연결하는 Branch로 구성됨

Root Node - 트리가 시작되는 가장 최상단의 노드. 전체 데이터셋을 포함. 첫 번째 질문(분할 조건) 주어짐.

Internal Node - 중간에서 조건(질문)을 테스트하는 노드. 특정 변수를 기준으로 데이터를 두 갈래 이상으로 나눔

Leaf Node / Terminal Node - 트리 가장 끝자락. 최종적인 예측값이 결정됨

​

데이터를 나누는 기준 : 불순도(Impurity) 줄이기

한 노드 안에 동일한 정답을 가진 데이터들만 모이도록(순도를 높이도록) 질문을 잘 고르는 것이 핵심. 데이터가 얼마나 섞여 있는지를 수치화한 것이 불순도

​

불순도 측정 지표

(1) 지니 불순도 (Gini Impurity) : 계산속도 빠름

(2) Entropy : 데이터의 무질서도를 나타냄. 지니 불순도와 유사하게 혼잡도를 측정

​

장점

해석력과 직관성 : 시각적으로, 규칙으로 쉽게 이해 가능

전처리 최소화 : 수치화, 범주형 데이터를 모두 다룰 수 있음. 데이터 스케일링(정규화/표준화) 과정이 거의 필요 없음. 이상치에도 비교적 강함

​

단점

과적합(Overfitting) 발생할 위험 크다.

불안정성 : 데이터가 조금만 바뀌어도 트리 모양이 완전 달라질 수 있음

​

단점 극복 - 앙상블(Ensemble) 기법

여러 개의 트리를 만들어 그 의견을 종합하는 앙상블 기법

Random Forest : 여러 개의 트리를 독립적으로 만들고 투표를 통해 결과 결정

(ex) 부동산 정책을 사회학자, 국토부장관, 일반인, 임대사업자에게 물음 -> 4개 트리 중 다수결로 의견을 결정

(ex) 기상청에서 가장 많이 사용

Gradient Boosting(XGBoost, LightGBM 등) : 이전 트리의 오차를 보완하는 방향으로 다음 트리를 연속적으로 만들어 성능을 극대화

8. 참고 : LightGBM

XGBoost, LightGM 둘 다 **\*\*정형 데이터**\*\* 분석 알고리즘

XGBoost

트리의 같은 층에 있는 모든 노드를 다 쪼갠 다음 다음 층으로 넘어감

트리가 좌우대칭으로 균형 -> 과적합(Overfitting)에 매우 강함

데이터가 1만건 이하로 적거나 노이즈가 많을 때 매우 안정적

(단점) 별로 중요하지 않은 노드를 계산해야 해서 시간 오래 걸림

​

LightGBM

하나의 값만 선택하므로 처리 속도가 빠름

​

실무적 차이점

범주형 데이터(Categorical Data) 처리 : LightGBM - 자체적으로 범주형 변수 인식하고 최적으로 나눔

(XGBoost는 원핫인코딩 하는 사전 작업 필요)

히스토그램 기반 최적화 : LightGBM은 데이터를 구간(Bin)으로 묶어서 뭉텅이로 계산. 속도 극대화

​

XGBoost - 데이터 작거나 (1만~5만 건 이하), 안정성 제일 중요할 때

LightGBM - 데이터가 아주 크고, 빠른 학습 속도와 메모리 절약이 필요할 때 (실무에서 가장 많이 사용)

9. 참고 : 과적합 (Overfitting)과 드롭아웃(Drop Out)

[과적합 (Overfitting)]

Training Data에만 지나치게 over-fitted되어서, 처음 보는 test data나 실전 환경에서 예측성능이 떨어지는 현상

과소적합 (Underfitting)

​

과적합 발생 원인

모델이 너무 복잡할 때 : Layer과 parameter가 데이터 수에 비해 지나치게 많음

훈련 데이터 부족

학습을 너무 오래 했을 때 (Epochs 너무 클 때)

​

과적합 해결

데이터 늘리기

모델 단순화 : 조기 종료 / 가지치기(Pruning, 의사결정트리에서 사용)

가중치 규제 : 활성화 함수에서 규제함

Dropout : 흔히 사용되는 방법. 신경망의 노드 개수를 줄임

앙상블(Ensemble) : 한 모델의 과적합을 다른 여러 모델이 상쇄하도록 여러 모델 의견 종합 (Random Forest, Gradient Boosting(XGBoost, LightGBM 등))

---

10. 참고 : 과소적합 (Underfitting)

과소적합 주요 원인

모델이 너무 단순

학습을 충분히 하지 않음

특성 데이터가 부족하거나 부적절

규제가 너무 강함 : Dropout의 강도가 너무 세다

​

해결

모델의 복잡도 증가 : 은닉층 추가 / 의사결정 트리 - 트리 최대 깊이 늘려줌

충분한 학습

더 좋은 특성 추가

규제 완화 : Dropout rate(드롭아웃 확률)을 낮춤

11. 참고 : 조기 종료 (Early Stopping)

작동 원리 - Patience 설정

[![]({{ '/assets/images/naver-import/4227e6f077ff/img-002.png' | relative_url }})](#)

손실이 튀는 경우를 얼만큼 참을 것인가(누를 것인가) -> Patience

​

사용 예시

​

# 조기 종료 콜백(Callback) 설정
early_stopping = tf.keras.callbacks.EarlyStopping(
monitor='val_loss', # 모니터링할 지표 (검증 데이터의 손실) \*검증 데이터 손실값 반드시 저장
patience=5, # 5번의 Epoch 동안 개선되지 않으면 멈춤
restore_best_weights=True # True : 가장 성능이 좋았던 가중치로 자동 복구
)

# 모델 학습 시 callbacks 인자에 추가
model.fit(
X_train, y_train,
validation_data=(X_val, y_val), # 검증데이터
epochs=100, # 최대 100번 학습하라고 설정했지만 (컴퓨터 성능 좋으면 100부터, 나쁘면 10부터 설정하기)
callbacks=[early_stopping] # 조기 종료 조건이 맞으면 중간에 멈춤
)

12. 참고 : Keras 콜백(Callback)의 다른 기능

callbacks = [EarlyStopping변수, ModelCheckpoint변수] 리스트로 던져짐

Early Stopping는 콜백 함수 중 하나

(1) ModelCheckpoint (모델 중간 저장하기)

이 콜백은 매번 Epoch가 끝날 때마나, 혹은 이전보다 모델의 성능이 좋아졌을 때만 모델의 상태파일을 자동 저장

checkpoint = tf.keras.callbacks.ModelCheckpoint(
filepath='best_model.h5', # 저장할 파일명
monitor='val_loss', # 저장 기준이 될 지표
save_best_only=True # True면 최고 기록을 갱신할 때만 덮어쓰기 저장
)

(2)ReduceLROnPlateau (학습률 자동 조절하기)

reduce_lr = tf.keras.callbacks.ReduceLROnPlateau(
monitor='val_loss',
factor=0.2, # 갱신이 안 되면 학습률을 현재의 20% 수준으로 줄임
patience=3 # 3번의 Epoch 동안 개선이 없으면 발동
)

(3) TensorBoard (학습 과정 시각화 기록하기)

현재는 있는지 확인안됨. 잘 사용하지 않음

​

실전 적용 (콜백 묶어 쓰기)

# 모델 훈련 (fit) 시 callbacks 인자에 리스트로 전달
model.fit(
X_train, y_train,
epochs=100,
callbacks=[early_stopping, checkpoint, reduce_lr] # 변수명 나열한 리스트
)

13. 참고 : Transformer

모든 AI 언어 모델 (GPT, BERT, Claude)의 표준

​

트랜스포머 원리

기존 RNN 방식 (순차 처리)

한 단어 처리 끝나야 다음 단어 처리. GPU로 병렬 연산 할 수 없어 학습 속도 느림

트랜스포머 방식 (병렬 처리 + 어텐션)

모든 단어를 동시에 입력받음

​

핵심 원리 1. Self-Attention

문장 안의 한 단어가 그 문장 안의 다른 모든 단어들과 얼마나 연관되어 있는지 스스로 계산하는 메커니즘

핵심 원리 2. 위키 인코딩 Positional Encoding

트랜스포머는 RNN과 달리 모든 단어를 한 번에 입력받기 때문에 단어의 순서를 알 수 없다.

위치 인코딩을 사용해 각 단어의 원래 데이터에 그 단어의 문장 속 위치 정보를 담은 특수한 숫자 패턴을 더해준다,

​

트랜스포머 구조

인코더 Encoder

입력된 문장 전체를 읽고, 셀프 어텐션을 통해 단어들 간의 관계와 문맥을 완벽하게 이해하여 숫자 형태의 요약본으로 만듦(구글의 BERT-Gemini)

디코더 Decoder

인코더나 넘겨준 요약본을 바탕으로, 우리가 원하는 결과 문장을 한 단어씩 순차적으로 생성 (OpenAI의 GPT)

​

(참고) 단어 간 거리 측정 방법 - 유클리디안 거리, 레벤슈타인 거리

주어진 앞의 단어들을 바탕으로 바로 다음에 올 단어가 무엇일지 확률적으로 얘측하는 방식

새로운 문장을 만들어내는 데 압도적으로 강하다.
